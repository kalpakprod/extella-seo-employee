# System Blueprint: Extella SEO Employee

## Назначение

- **Blueprint:** `BP-SEO`, версия `2.0.0`, стадия `local release candidate, closed pilot`.
- **Область:** Blueprint определяет техническую композицию Продукта. Blueprint НЕ определяет пользовательское обещание и НЕ заменяет Feature Contract.

## Композиция

- **BP-SEO-001, тип продукта:** Продукт является гибридным ИИ-приложением Extella. Панель живёт в Extella, а выполнение и данные живут на клиентском сервере.
- **BP-SEO-002, поверхность:** Панель получает устройство из `etb_init.device`, затем вызывает собственного эксперта-диспетчера сообщением `etb_run_expert` с singular `target`. Без `device` bridge завершает вызов видимой ошибкой через пять секунд. Это JS bridge contract, а не REST contract: `targets` Панель не передаёт.
- **BP-SEO-003, диспетчер:** Эксперт `seo_employee_run` принимает команду Запуска и возвращает `run_id`. Эксперт `seo_employee_state` возвращает текущее состояние и последний завершённый Снимок.
- **BP-SEO-004, исполнение:** Agent Zero выполняет модельно-независимый последовательный процесс SEO Runner. Конкретные provider, model и способ доступа выбираются пользователем в конфигурации Agent Zero и не входят в бизнес-логику Сервиса. До любого `HTTP POST` Сервис ОБЯЗАН проверить точный профиль `seo_employee_no_tools`: tool policy и skill policy блокируют всё. Agent Zero НЕ создаёт отдельный пользовательский кабинет, отдельную продуктовую память или вторую личность Продукта.
- **BP-SEO-005, методика:** Контракты используют категории claude-seo, но сторонний главный `/seo` и новый агентный фреймворк не создаются. Agent Zero получает только закрытый Вход модели из `SC-SEO-031`.
- **BP-SEO-006, данные сайта:** CrawlSEO выполняет ограниченный публичный обход до 100 страниц через MCP. PostgreSQL CrawlSEO хранит crawl и опциональные GSC/CWV/opportunities. DNS-only container обслуживает только `/health` и `/resolve`. Оба source worker загружают `safe_fetch`: URL с credentials, частным DNS-ответом или unsafe redirect отклоняется до запроса.
- **BP-SEO-007, независимая проверка:** SEOmator CLI выполняет 20 категорий и распознаёт 251 закреплённое правило. Дорогие Performance/JS категории запускаются на детерминированной выборке до пяти indexable URL отдельно от основного crawl.
- **BP-SEO-007a, lifecycle и deadline источника:** `/run` удерживает занятость до завершения или принудительного завершения audit-процесса. При обрыве клиента worker завершает Linux process group и дожидается exit. Одностраничный deadline равен `180/120` секунд, multi-page — `900/720`; успешный child повторно не убивается.

## Хранение

- **BP-SEO-008, Снимки:** SEO Runner хранит завершённые Снимки и текущее состояние в локальном каталоге Продукта. Запись использует временный файл и атомарную замену.
- **BP-SEO-009, Базовая линия:** Только `ready` Снимок совместимого target/plan/catalog major становится Базовой линией. `partial` и `failed` её не заменяют и не объявляют исчезнувшие проблемы исправленными.
- **BP-SEO-010, секреты:** Секреты хранятся только в `deploy/secrets` вне образов, релизного архива и Снимков. Compose монтирует файлы режима `600`; bootstrap читает их до необратимого перехода процесса на UID/GID `10001` и переносит только в `tmpfs`. Значения НЕ передаются в Extella, Agent Zero prompt, журнал или отчёт.

## Расписание и состояние

- **BP-SEO-011, расписание, очередь и реплика:** Суточный триггер проверяет все Цели и помещает due-запуски в атомарную FIFO `state/queue.json`. Один consumer явно восстанавливает interrupted item при старте и выполняет source-heavy Запуски последовательно. Compose рассчитан на одну реплику.
- **BP-SEO-012, привязки:** `prepare.py` записывает локальные `device_binding.json` и `agent_binding.json` только после проверки канонических device и agent identifiers. До byte-for-byte проверки файлов профиля внутри Agent Zero assertion no-tools profile не создаётся. Отсутствующая, частичная или неверная привязка в состоянии отображается как `null`, а не как выдуманная идентичность.
- **BP-SEO-013, состояние Extella:** Панель читает `extella.seo_employee_state.v2` выбранной Цели и `extella.seo_employee_report.v2`. Targetless чтение возвращает безопасные summaries для выбора Цели; очередь содержит только публичные поля.

## Права и данные

- **BP-SEO-014, права Extella:** Продукт запрашивает только `expert.run` и `device.run`; `device.run` нужен для singular bridge `target` и не даёт `api.full`, `*.write` или разрушающие операции. V2 gate `check_app_scopes.py` должен быть повторно подтверждён перед релизом.
- **BP-SEO-015, внешние Источники:** CrawlSEO может читать уже подключённые GSC/CWV/opportunities; без read-only credentials режим возвращает `not_configured`. DataForSEO остаётся отдельным optional lane с budget cap. Индексирующие и записывающие Google API запрещены.
- **BP-SEO-016, контур:** Сырые данные CrawlSEO и SEOmator остаются на клиентском сервере. Agent Zero получает только Вход модели, прошедший список разрешённых полей и запретов `SC-SEO-031`.

## Проверенная граница реализации

- **BP-SEO-017, исторический baseline транспорта Agent Zero:** 29.08.2026 на CT160 был зафиксирован локальный `HTTP POST` к `/api/api_message` и живой маршрут `agy/gemini-3.7-flash-high`. Это старое доказательство baseline, а не доказательство текущего архива. Код принимает ответ только формы `{"context_id":"<непустая строка>","response":"<строка>"}`, использует `X-API-KEY`, no-tools profile `seo_employee_no_tools` и timeout `60` секунд в общем deadline `180` секунд.
- **BP-SEO-018, модельная граница:** Продукт НЕ ДОЛЖЕН содержать allowlist моделей и автоматический fallback. До использования каждый точный provider, model и способ аутентификации ОБЯЗАН пройти отдельный живой вызов. Из известных маршрутов живым вызовом был подтверждён только `agy/gemini-3.7-flash-high`; это не доказывает BYOK, пользовательскую подписку или другой маршрут.
- **BP-SEO-026, исторический первый вертикальный срез:** На CT160 29.08.2026 `https://example.com/` прошёл ровно один `run_crawl` с `maxPages=1` и одну SEOmator CLI-проверку категории `core` без CWV и multi-page crawl. Оба Источника подтвердили одну нормализованную Находку `meta-description-missing` из пары `MISSING_DESCRIPTION` и `core-description-present`. Это старый baseline клина, а не доказательство текущего архива или реальных pilot data.
- **BP-SEO-027, изолированный runtime:** Compose разделяет `control`, отдельные `crawlseo_control`, `resolver_control`, `seomator_control`, внутреннюю сеть базы, отдельные egress-сети и `ingress`. `seo-employee` подключён только к четырём internal‑сетям и не имеет прямого egress или опубликованного порта. DNS-only resolver подключён только к `resolver_control` и собственной egress-сети, не имеет порта, secrets или volumes и не исполняет `/run`. Непривилегированный `api-gateway` публикует API только на `127.0.0.1`; отдельный `agent-zero-proxy` пропускает только `/api/api_message`. CrawlSEO использует PostgreSQL без опубликованного порта, образ `postgres@sha256:d3e1620b530c944afa6e887d22eb899824da68e19c52024bf98f5220c88a65b2`. Пароли остаются в secret‑файлах режима `600`.
- **BP-SEO-028, минимальная адаптация CrawlSEO:** Патч `patches/crawlseo-one-page-cap.patch` передаёт `maxPages` в `runSiteCrawl` и сохраняет фактический предел. Название файла историческое; реализация поддерживает bounded значение `1..100`. CT160 должен доказать multi-page предел отдельно.
- **BP-SEO-029, воспроизводимая упаковка источников:** В закреплённом CrawlSEO runtime добавляет `tsx@4.23.12`; рассинхронизированный SEOmator package metadata нормализуется до `npm ci`. Предыдущая чистая сборка и одностраничный прогон от 30.08.2026 являются baseline. Текущему архиву требуется отдельная root-проверка этих действий.
- **BP-SEO-030, release-политика Extella:** Модельно-независимый паспорт не объявляет `provider_expected`. Пакет 2.0 является локальным RC для закрытого Linux `amd64` pilot до чистой Docker/CT160 проверки. Публикация и platform binding требуют отдельного разрешения и аутентификации.
- **BP-SEO-031, неподтверждённая доступность моделей:** Собственная подписка, BYOK и каждый маршрут, кроме `agy/gemini-3.7-flash-high`, остаются гипотезами до отдельного живого вызова. Экран тарифов или сохранённая настройка не являются доказательством маршрута.
- **BP-SEO-032, переносимая установка и откат:** `install.py` проверяет manifest, требует Linux, Docker и канонический `EXTELLA_AGENT_ID`, затем копирует payload атомарно. При замене существующих файлов installer сохраняет только затронутые прежние файлы и `rollback.json` в локальном каталоге backups. `prepare.py` создаёт секреты, привязки, runtime и pinned Compose; существующий закреплённый Agent Zero МОЖЕТ подключаться к `control` без перезапуска. Ни Docker socket, ни credentials модели в продукт не монтируются.
- **BP-SEO-033, исторический контейнерный E2E:** CT160 ранее подтвердил health, preflight, ручной и суточный Запуск, `duplicate` и сохранение после рестарта. Этот результат относится к прежнему baseline CT160 и не доказывает текущий архив. Финальная root-проверка должна заново подтвердить staging-стек и артефакт.

## Внешние инструменты вне рабочего цикла

- **BP-SEO-019, OpenExecutive:** OpenExecutive МОЖЕТ проводить продуктовый разбор перед выпуском. Он НЕ участвует в ежедневном или ручном Запуске клиента.
- **BP-SEO-020, llm-council:** llm-council МОЖЕТ выполнять независимую оценку релизного Снимка. Он НЕ является Источником фактов SEO Runner.
- **BP-SEO-021, отложенные компоненты:** OpenSEO, Agent Reach, OpenCLI и `academic-research-skills` НЕ входят в MVP. Компонент добавляется только через новую норму Feature Contract и соответствующие Component Contracts.
