# Wave 6 task: PSI-лейн (PageSpeed Insights как performance-источник)

Статус: задача расписана, не начата. Гейт: решение D2 релизного плана
(`docs/plans/2026-09-14-production-release.md`).

## Зачем

Сейчас performance и JS-rendering покрываются максимум пятью страницами
детерминированной выборки двух движков, а `search_performance` без credentials —
`not_configured`. PSI API v5 даёт независимый третий замер perf-метрик по HTTP,
вызывается из stdlib (`urllib`) и не нарушает запрет на зависимости в
прод-Python. Это первый кандидат в Wave 6 вместо локального Lighthouse
(тяжёлый, труднее детерминировать).

Источник: https://developers.google.com/speed/docs/insights/v5/get-started

## Объём работ

1. **Адаптер источника** `experts/seo_employee_psi.py` (stdlib-only):
   запрос к PSI API по URL из AuditPlan, таймауты и ретраи как у существующих
   lane, классификация статусов по действующей шкале
   (`ok/not_configured/unavailable/failed/unsupported` — см. CT-SC-004 в
   `docs/verification/traceability.md`).
2. **Контракты:** новые/расширенные нормы Service Contract для PSI-лейна
   (лимиты выборки, маппинг метрик в evidence, поведение без ключа —
   `not_configured`, блокировки бесплатного аудита нет).
3. **Evidence:** PSI-факты идут в общий evidence-пакет с указанием источника;
   corroboration — только по rule-specific правилам каталога
   (`experts/rule_catalog.v2.json`), без слияния «двух произвольных источников».
4. **Секреты:** API-ключ (если потребуется) — только через файл секретов по
   образцу `deploy/secrets/` + `*_FILE`; никогда в репо и логах (H71).
5. **Тесты:** `tests/test_seo_employee_psi.py` — контракт адаптера на фикстурах
   (без живых вызовов в юнит-сюите), статусы, таймауты, отсутствие ключа;
   живой smoke — отдельным ручным шагом с квотой.
6. **Доки:** обновить service contract, `claim-evidence.md` (граница: что PSI
   доказывает, а что нет), README-матрицу при необходимости.

## Границы и риски

- Проверить ToS и квоты PSI до включения в дефолтный путь; превышение квоты —
  честный `unavailable`, а не молчаливый пропуск.
- Не заявлять «рост скорости/позиций» — только измеренные метрики с источником.
- Лицензия/условия Google API — в license review (см. T5.1 релизного плана).

## Приёмка

- `python -m unittest discover -s tests -p "test_*.py"` зелёный (включая новый файл).
- `check_code_canon` и `check_ready_for_publish` апстрима — зелёные.
- Ручной smoke на 1 публичной странице: evidence содержит PSI-факты с источником;
  без ключа — `not_configured`, аудит не блокируется.
