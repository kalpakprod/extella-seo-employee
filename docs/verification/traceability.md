# Contract Traceability: Extella SEO Employee

## Правило соответствия

- **Источник поведения:** Feature Contract определяет требуемое поведение Продукта.
- **Источник реализации:** Service Contract и UI Contract определяют логику компонентов, которая реализует Feature Contract.
- **Источник тестов:** Contract Tests создаются только из норм Service Contract и UI Contract.
- **Роль Blueprint:** Blueprint ограничивает техническую композицию. Blueprint НЕ закрывает норму Feature Contract самостоятельно.

## Проверка документации

- **Полнота Feature Contract:** Каждая норма `FC-SEO-*` ОБЯЗАНА встречаться в разделе соответствия ровно один раз.
- **Полнота Component Contracts:** Каждая норма `SC-SEO-*` и `UC-SEO-*` ОБЯЗАНА быть источником хотя бы одного `CT-*`.
- **Однозначность:** Один `CT-*` МОЖЕТ проверять несколько связанных норм одного поведения. Тест НЕ ДОЛЖЕН вводить поведение, которого нет в Component Contract. Историческое v1 CT160 baseline не является проверкой текущего архива v2.
- **Планируемая v2 проверка прав:** До Task 11 gate должен отдельно распознать REST `targets` и JS bridge `etb_run_expert` с singular `target`; negative controls должны запретить случайному `event.target` запросить `device.run`. Эта норма не заявляет, что текущий `check_app_scopes.py` уже покрывает v2.
- **Изменение:** Изменение нормы ОБЯЗАНО обновить соответствие и затронутый Contract Test в том же изменении.
