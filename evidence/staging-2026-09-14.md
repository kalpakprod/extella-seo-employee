# Staging proof — 2026-09-14

Проект `extella-seo-staging` на том же хосте (отдельный Compose-проект, чистые
вольюмы, отдельные loopback-порты). Подъём строго командой из документации, без
импровизаций. Секреты/bindings общие с основным контуром — на отдельном хосте
вместо этого выполняется полный `prepare.py` (см. `deploy/README.md`).

## Подъём

```sh
SEO_EMPLOYEE_PORT=18088 AGENT_ZERO_PORT=50082 docker compose \
  --project-name extella-seo-staging -f deploy/compose.yaml \
  --profile managed-agent-zero up -d
```

Результат: все 8 контейнеров healthy (agent-zero-proxy без healthcheck по дизайну).
`GET http://127.0.0.1:18088/health` → 
`{"status":"ok","version":"2.0.3","queue":{"depth":0,"consumer":"alive"}}`.

## Функциональная проверка

- `POST /api/preflight` → 503 `SEO_PREFLIGHT_FAILED` («Маршрут модели не прошёл
  безопасную проверку») — честно: у стейджингового Agent Zero нет LLM-провайдера.
- `POST /api/configure` (books.toscrape.com, service_b2b, full_audit, 5 страниц) → ok.
- `POST /api/run` → queued `seo-49a9378391…` → `completed` (~4 мин).
- Отчёт: 10 задач, просканировано 5/5, `last_error: null`,
  `model_enrichment: 0/10 unavailable` с текстом
  «One or more model enrichments are unavailable; deterministic evidence is preserved.»
  Детерминированный fallback без провайдера работает, аудит не падает.

## Адреса

- API: `http://127.0.0.1:18088` (поднять: команда выше; остановить:
  `docker compose --project-name extella-seo-staging -f deploy/compose.yaml down`).
- Agent Zero UI: `http://127.0.0.1:50082`.
- TLS поверх — только по `deploy/TLS-INGRESS.md`; живое завершение требует хоста
  с доменом (open question 3 плана).
