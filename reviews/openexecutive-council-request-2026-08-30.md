# Бриф для совета OpenExecutive: Extella SEO Employee 1.0.0

Это аудит отдельного продукта. Текущий company profile OpenExecutive относится к другому проекту и НЕ ДОЛЖЕН использоваться как доказательство или контекст для решения.

## Что проверяется

«SEO-сотрудник: аудит и контроль» для Extella. Целевой пользователь первой версии: владелец или руководитель маркетинга малого B2B-бизнеса. Продукт по запросу и раз в сутки проверяет один публичный URL, сопоставляет результаты двух независимых SEO-источников, формирует до 10 проверяемых задач и показывает изменение относительно прошлого завершённого снимка. Он ничего не публикует, не индексирует и не меняет на сайте.

Это закрытый pilot RC, а не универсальный автономный SEO-отдел. Текущий проверяемый клин умеет достоверно выявлять только отсутствие meta description на одной странице.

## Техническая композиция

- Extella: панель и запуск двух Experts, `seo_employee_run` и `seo_employee_state`.
- Agent Zero 2.11: только объясняет business impact и minimal fix для уже подтверждённой находки; профиль `seo_employee_no_tools`, tools и skills отключены.
- CrawlSEO: MCP-обход, жёстко ограниченный одной страницей.
- SEOmator: независимая CLI-проверка той же страницы.
- Локальное версионированное состояние и отчёт: `extella.seo_employee_state.v1` и `extella.seo_employee_report.v1`.
- Docker Compose: 7 сервисов, внешние API по умолчанию доступны только на loopback.
- Google Search Console в 1.0.0 не подключается и явно обозначается `not_configured`.
- Пользователь может выбрать модель и способ доступа в Agent Zero. Подтверждён только маршрут `agy/gemini-3.7-flash-high`; собственная подписка, BYOK и другие модели остаются неподтверждёнными до отдельной живой проверки. Автоматический fallback запрещён.

- Локально: 51 Python test и 33 Node test, self-check, contract/UI gates и детерминированная повторная сборка прошли.
- CT160: все 7 сервисов healthy; ручной и суточный запуски завершились `ready`; повторный суточный и параллельный запуск дедуплицированы.
- Поддержаны и проверены `partial` и `failed`; partial не заменяет базовую линию.
- После SIGKILL продукт перезапустился, состояние сохранилось; stale lock восстановлен без двойного победителя.
- При разрыве клиента оба SEO-worker прекратили работу; orphan processes: 0.
- SSRF: прямые private/control URL и public-to-private redirect заблокированы; DNS-only resolver не предоставляет run-route.
- Agent Zero: 21 проверенный свежий context, tool contexts: 0.
- Backup create/verify и временная restore-check прошли.
- Переносимый runtime ZIP: `extella-seo-employee-runtime-1.0.0.zip`, SHA-256 `3185640f4dee808cf9ce95b9fceed6e7c32870d631fbfa57eb06f199c402a12b`.

## Не проверено

- Реальная аутентификация Extella, привязка агента/устройства, публикация и путь покупателя.
- Реальные пилотные сайты и пользовательские результаты.
- Спрос, willingness-to-pay, retention, CAC, LTV, стоимость одного запуска и investor/commercial numbers.
- Модельные и auth-маршруты, кроме `agy/gemini-3.7-flash-high`.

## Задание совету

Проведите фактический межфункциональный разбор. Обязательно привлеките продуктовый, стратегический, маркетинговый, операционный, финансовый и юридический взгляд. Не принимайте утверждения из брифа сверх перечисленных доказательств; каждое существенное утверждение помечайте как FACT, INFERENCE или HYPOTHESIS.

Дайте один окончательный ответ на русском в следующей структуре:

1. Вердикт: `SHIP_CLOSED_PILOT`, `FIX_BEFORE_PILOT` или `BLOCK`.

5. До пяти P0/P1-проблем, только если они реально блокируют закрытый пилот или создают существенный риск.
6. Один следующий build slice для Максима как веб-разработчика, максимум 5 конкретных задач с проверяемым результатом.
7. Что сейчас не строить.
8. 30-секундный инвесторский питч без неподтверждённых цифр.
9. Таблица investor claims: что уже можно заявлять, что нельзя заявлять, какое доказательство нужно.
10. Финальное решение председателя в 5 строках.

Не предлагайте переписывать существующий стек или строить новый agent framework без доказанного блокера.
